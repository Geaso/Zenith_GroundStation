# LR24 数传配对协议与接入约束

本文记录 GroundStationQt 使用的 MicoAssistant/LR24 本地配置协议。协议来自 2026-08-27 对
MicoAssistant v1.0.3 公开前端程序的分析，并与 LR24 官方用户手册的地址、波特率和工作模式
说明交叉核对。它不是厂家承诺长期兼容的公开 API；升级 MicoAssistant 或数传固件后必须重新
抓包验证。

参考：

- <https://micoair.cn/zh/docs/telemetry/lr24/lr24-telemetry>
- <https://micoair.com/assistant/>

## 1. 串口与独占关系

配置对象是 USB 连接的本地数传模块，不经过空口，也不要求先与飞机侧数传建立链路。
串口采用 8 数据位、1 停止位、无校验、无流控。探测 USB 波特率按实际产品配置进行；LR24
官方列出的 USB 波特率为 57600、115200、921600。

配置读写和正常遥测共用同一个 COM 口，必须由一个串口状态机独占管理，不能让两个
`QSerialPort` 实例同时打开。进入握手阶段后暂存或暂停 Zenith 业务帧处理，完成回读确认后再
切回正常收发。不要在已有遥测收发期间另开端口探测。

## 2. 帧格式

所有多字节整数均为小端序。

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 1 | 帧头，固定 `0xEF` |
| 1 | 1 | `deviceId` |
| 2 | 1 | `systemId` |
| 3 | 1 | `messageId` |
| 4 | 1 | `sequence`，发送方逐帧递增，溢出后回绕 |
| 5 | 1 | `payloadLength`，本实现接受 0..100 |
| 6 | N | payload |
| 6+N | 1 | checksum |

校验和为校验字节之前所有字节的无符号和取低 8 位：

```text
checksum = sum(frame[0 .. 5+N]) & 0xFF
```

设备号与消息号：

```text
PC_GCS  = 1       RADIO   = 30
HEARTBEAT = 1     CMD     = 2     CMD_ACK = 3
```

流式解析器必须保留不完整帧；遇到噪声、超长负载或校验失败时报告明确错误，并重新搜索下一
个 `0xEF`，不能把错误数据静默当作遥测。

## 3. 识别心跳

配置阶段的识别重试会发送 13 字节配置心跳；当前实现每 500 ms 重试一次，外层帧为：

```text
deviceId = 1 (PC_GCS)
systemId = 0（识别前）
messageId = 1 (HEARTBEAT)
```

心跳 payload：

| 偏移 | 类型 | 值/含义 |
|---:|---|---|
| 0 | `uint32` | 当前系统时间低 32 位 |
| 4 | `uint8` | `productModel = 30`，表示 Radio Config |
| 5..8 | 4 字节 | `00 01 00 01` |
| 9 | `uint32` | 0 |

没有发现 `+++` 或 AT 指令入口。数传心跳返回帧的 `deviceId=30`；记录其帧头中的
`systemId`，后续 CMD 必须使用这个值。返回心跳 payload 至少 13 字节，其中偏移 4 是实际
产品型号，偏移 5 是硬件版本，偏移 6、7、8 分别是软件 patch、minor、major。

已知 LR24 型号为 2（LR24）、32（LR24-F）、33/34（LR24-P）。

## 4. 参数命令和地址位置

CMD payload 开头是小端 `uint16 commandId`。查询 CMD 只有这两个字节；设置 CMD 的完整
payload 固定为 18 字节，不足部分补零。设备以 `CMD_ACK` 回复，ACK payload 开头同样是
`uint16 commandId`，其后才是参数区。

| 产品型号 | 参数版本 | GET | SET | 参数区最小长度 |
|---|---:|---:|---:|---:|
| 2、3、4、16、18、32、34 | V2 | 3 | 4 | 9 |
| 33 | V3 | 5 | 6 | 10 |
| 48、49 | V4 | 7 | 8 | 12 |
| 其他 | V1 | 1 | 2 | 8 |

各版本参数区的地址位置都相同：偏移 4 是小端 `uint16 moduleAddr`。V2 参数布局如下：

| 参数偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | `uint8` | workMode |
| 1 | `uint8` | airSpeed |
| 2 | `uint8` | txPower |
| 3 | `uint8` | freqChannel |
| 4 | `uint16` | moduleAddr |
| 6 | `uint8` | uartBaudRate |
| 7 | `uint8` | freqMode |
| 8 | `uint8` | usbBaudRate |

V3 在末尾增加 `moduleType`，V4 再增加 `slaveCount`、`slaveIndex`。设置地址时必须先 GET，
复制当前型号的完整参数区，只改偏移 4..5，再发送对应 SET。禁止凭默认值拼出其他字段，否则
可能同时改坏速率、功率、频点或地面/空中角色。SET ACK 后仍需再次 GET，以回读值作为成功
依据；仅收到写入 ACK 不算完成。

## 5. 推荐握手时序、超时和重试

```text
独占打开 COM
  -> 每 500 ms 发送配置心跳，等待 RADIO 心跳
  -> 记录 productModel 与 systemId
  -> GET 对应版本参数
  -> 显示读回的 moduleAddr
  -> 以完整旧参数构造 SET，只替换 moduleAddr
  -> 等待匹配命令号的 SET CMD_ACK
  -> 再次 GET
  -> 地址一致：结束配置阶段，清理配置解析缓冲，进入正常遥测
  -> 地址不一致或任一步失败：明确报错，不静默进入正常收发
```

当前生产实现先等待串口稳定 280 ms，随后按 500 ms 间隔重试：识别心跳最多 6 次，GET、
SET ACK 和写后 GET 各最多 4 次；收到 SET ACK 后再等待 300 ms 才做回读。每次重试都重发
当前阶段的完整请求并使用新的 sequence。整个成功切换实测通常小于 1 秒；识别失败约 3 秒，
单个命令阶段失败约 2 秒，具体取决于驱动调度和模块固件。界面从开始握手就显示“正在配置
数传”，在成功前不宣称串口已连接。

下列情况应使用不同错误文本：未收到数传心跳、产品型号不支持、参数 ACK 命令号不匹配、
参数长度不足、帧校验失败、写入 ACK 超时、写后回读不一致、串口被占用或设备已拔出。

切换过程中正常遥测会中断，因为同一串口正在交换配置帧。中断持续时间就是上述握手时间；
实现应在切换前停止业务心跳/指令发送，成功或失败后显式恢复/关闭，而不是把两种协议混发。

## 6. 地址范围与产品策略

LR24 官方硬件地址范围是 **1..30000**，默认地址是 1000；只有地址一致的两个模块才能空口
通信。本协议层因此能读写 1..30000，并把 1000 作为合法硬件值。

GroundStationQt 本期采用更窄的产品策略：

- 可分配给飞机的统一编号为 **1..254**，让数传地址与单字节 `uav_id` 保持相同；不需要另建
  映射表。
- 255 保留，0 不可用。
- 1000 是“未配对/出厂态”哨兵，只能显示为未配对，不能作为飞机编号。

所以“硬件协议可写 1..30000”和“配对表只允许 1..254”并不冲突：前者属于编解码层，后者
属于产品校验层。如果将来飞机数超过 254 台，必须先定义分段或显式映射规则，不能直接放宽
界面校验。

## 7. 飞机侧与快速切换边界

飞机侧 LR24 地址不是不可变序列号。它和地面侧一样可通过本地 USB/串口配置，通常在装机或
出厂时设为该机编号；本期地面站只自动改地面端数传狗，不远程改飞机端。地址不匹配时没有
空口链路，因此也不能通过地面狗隔空发现或修改飞机侧地址。

数传狗只能保存一个当前地址，没有发现“多个地址配置槽”。即使应用层缓存了多条配对记录，
每次换飞机仍必须走完整的心跳 -> GET -> SET -> GET 回读流程。不能只在内存里切换，也不能
根据 CP2102 序列号推断射频地址。

## 8. 对目标文档第 7 节问题的直接回答

1. **地址空间**：硬件为 1..30000；本产品只分配 1..254，并与 `uav_id` 取相同值。1000 是
   未配对哨兵，255 保留。
2. **是否独占串口**：是。配置和遥测使用同一 COM，必须由同一状态机串行执行。
3. **遥测是否中断**：会。中断覆盖整个配置握手，通常约 0.1..1.5 秒；超时重试时更长。
4. **飞机侧地址来源**：可配置，并非厂家不可变 ID。应在装机/出厂时本地写成机身编号；本期
   不修改飞机侧。
5. **能否记多个地址**：模块只保留一个当前地址。应用层可以记配对表，但每次切换都必须完整
   握手、写入并回读确认。
